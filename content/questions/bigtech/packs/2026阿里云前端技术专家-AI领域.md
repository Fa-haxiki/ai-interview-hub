### 请简述 SSE（Server-Sent Events）与 WebSocket 的区别，以及在 AI 对话场景下为什么通常选择 SSE?

SSE 是一种基于 HTTP 的单向推送技术，而 WebSocket 是全双工的二进制协议。在 AI 场景下，SSE 因其轻量级和原生支持流式解析而成为首选。

- 协议层：SSE基于标准HTTP协议，支持自动重连，WebSocket则是独立的TCP协议。

- 数据格式：SSE 传输的是文本流（UTF-8），WebSocket 支持二进制和文本。

- 场景匹配：LLM输出是单向流式的，SSE建立连接简单，且能更好地穿透防火墙和代理。

- 资源消耗：SSE 在服务端压力相对较小，且支持 HTTP/2 多路复用。

- 忽略了 SSE 在 HTTP/1.1 下有 6 个连接限制的问题。

### 请手写一个简单的流式数据解析器，模拟处理 Fetch API 返回的 ReadableStream。

利用 response.body.getReader() 循环读取数据块，并通过 TextDecoder 将 Uint8Array 转换为字符串。

- 获取 Reader：通过 getReader() 获取流的读取器。

- 循环读取：使用 while(true) 循环配合 await reader.read()。

- 解码处理：使用 TextDecoder 处理字节流，注意处理跨 chunk 的字符截断。

- 异常处理：try-catch 捕获网络中断，并确保调用 reader.releaseLock()。常见坑：

- 忘记处理 done 状态导致死循环。

- 直接 toString() 导致中文字符在 chunk 边缘被截断产生乱码。

```javascript
async function fetchStream(url) {
    const response = await fetch(url);
    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    const chunk = decoder.decode(value, { stream: true });
    console.log('Received chunk:', chunk);
    }
}
```

4. 谈谈 Promise.all、Promise.allSettled 和 Promise.race 的区别，并举例 AI 场景下的应用。

### 谈谈 Promise.all、Promise.allSettled 和 Promise.race 的区别，并举例 AI 场景下的应用。

这三个方法用于处理多个并发异步任务，区别在于对“成功”和“失败”的判定逻辑不同。

- Promise.all：全部成功才返回，一个失败即整体失败。适用于 AI 批量生成摘要。

- Promise.allSettled：无论成功失败，返回所有任务的结果。适用于并行调用多个模型并对比结果。

- Promise.race：返回最快的结果。适用于多模型竞速，取响应最快的那个。

- 错误处理：allSettled 不需要 catch 每一个子项，而 all 必须处理。常见坑：

- 在 Promise.all 中忘记处理 catch，导致一个请求失败影响全部。

- 如果要实现一个带并发限制（如最多同时请求3个模型）的函数，你会怎么写？

### 谈谈 Web Worker 在 AI 前端应用中的实际应用场景。

Web Worker 主要用于处理计算密集型任务，防止主线程卡顿。

- Worker与主线程频繁通信导致的序列化开销。

- 在 Worker 中无法直接操作 DOM 的限制。
