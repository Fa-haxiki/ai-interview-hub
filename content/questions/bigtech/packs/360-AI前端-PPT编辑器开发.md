### 简单介绍一下 SSE（Server-Sent Events）和 WebSocket 的区别，为什么 AI 聊天场景多采用 SSE?

SSE是一种基于HTTP的单向推送技术，相比WebSocket更加轻量，且天然支持断线重连。

- 协议层：SSE基于标准HTTP协议，WebSocket是独立的TCP协议。

- 方向性：SSE是单向（服务端向客户端），WebSocket是双向。

- 兼容性：SSE能够通过HTTP代理和防火墙，支持自动重连。

- 场景匹配：AI生成内容是典型的单向长文本流，不需要双向高频交互，SSE实现成本更低。

- 忽略了 SSE 在 HTTP/1.1 下有 6 个并发连接限制。

- 认为SSE只能传输文本，其实可以通过Base64传二进制。

### 在开发PPT编辑器时，如果让你选择渲染引擎，Canvas和SVG你会怎么选？

Canvas 适合高性能、大量图形渲染的场景，而 SVG 适合高保真、需要 DOM 交互的矢量图形场景。

- 渲染模式：Canvas 是位图渲染（即时模式），SVG 是矢量图形（保留模式）。

- 交互性：SVG 元素自带 DOM 事件，Canvas 需要手动计算坐标实现交互。

- 性能表现：元素数量极多时 Canvas 性能占优，屏幕尺寸极大时 SVG 性能较好。

- PPT 场景：通常采用 Canvas 保证编辑流畅度，但在导出 PDF 或打印时会利用 SVG 的矢量特性。

#### 常见坑：

- 简单认为 Canvas 性能一定比 SVG 好，忽略了重绘成本。

#### 4. 说一下 Promise.all 和 Promise.allSettled 的区别，在调用多个 AI 接口时你会用哪个？

### 说一下 Promise.all 和 Promise.allSettled 的区别，在调用多个 AI 接口时你会用哪个？

Promise.all 要求全部成功，而 Promise.allSettled 会等待所有任务结束并返回每个任务的状态。

- 失败处理：Promise.all 只要有一个 reject 就会立即触发 catch。

- 返回结构：allSettled 返回包含 status 和 value/reason 的对象数组。

- AI场景：通常选择allSettled，因为即使某个AI插件或子任务失败，也不应影响其他模块的展示。

#### 常见坑：

- 在 Promise.all 中忘记处理 catch 导致整个链路中断。

6. 手写一个简单的防抖函数（Debounce），并解释它在编辑器保存场景下的作用。

### 手写一个简单的防抖函数（Debounce），并解释它在编辑器保存场景下的作用。

防抖是在事件触发后延迟执行，如果在延迟时间内再次触发，则重新计时。

- 核心实现：利用闭包存储timer变量，每次触发时clear掉之前的定时器。

- 应用场景：用户在PPT中拖拽元素或输入文字时，不应频繁触发保存接口，而是停止操作后500ms再保存。

```javascript
1 function debounce(fn, delay) {
2    let timer = null;
3    return function(...args) {
4    if (timer) clearTimeout(timer);
5    timer = setTimeout(() => {
6    fn.apply(this, args);
7    }, delay);
8    }
9 }
```

#### 常见坑：

- 丢失了 this 指向。

- 忘记处理参数传递。

### 解释一下 TypeScript 中的 Record&lt;string, any&gt; 和 object 有什么区别?

Record 提供了更具体的键值对约束，而 object 仅表示非原始类型。

- 访问权限：Record 定义后可以访问其属性，object 类型变量不能直接访问属性。

- 适用范围：object 包含数组、函数等，Record 通常用于定义普通的映射对象。

- AI 场景：定义 Prompt 模板参数时，通常使用 Record<string，string>。
