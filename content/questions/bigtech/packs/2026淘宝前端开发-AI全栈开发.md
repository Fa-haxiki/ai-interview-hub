### 浏览器中的事件循环（Event Loop）是怎么运作的？

事件循环是浏览器协调事件、用户交互、脚本、渲染和网络任务的机制，核心是任务队列的调度。

- 宏任务与微任务：宏任务包括script、setTimeout、I/O；微任务包括Promise.then、MutationObserver。

- 执行顺序：先执行一个宏任务，然后清空整个微任务队列，接着进行 UI 渲染，循环往复。

- 渲染时机：浏览器通常在微任务清空后、下一个宏任务开始前尝试进行页面重绘。

- 栈溢出：同步代码执行过久会阻塞事件循环，导致页面卡死。

常见坑：

- 误以为setTimeout(fn, 0) 是立即执行。

- 混淆 Node.js 事件循环与浏览器事件循环的区别。

### 在 AI应用中，SSE（Server-Sent Events）和 WebSocket 有什么区别？

SSE 是基于 HTTP 的单向通信协议，适合服务器向客户端推送文本流；WebSocket 是全双工通信协议，支持双向数据传输。

- 数据流向：SSE仅支持服务端到客户端；WebSocket支持双向实时通信。

- 协议开销：SSE基于标准HTTP，更轻量，支持自动重连；WebSocket需握手切换协议，开销相对较大。

- 数据格式：SSE 默认传输 UTF-8 文本；WebSocket 支持二进制和文本。

- AI 场景：大模型生成回复通常是单向流式输出，SSE 往往是更简单高效的选择。
常见坑：

- SSE 在 HTTP/1.1 下有浏览器连接数限制（通常为 6 个）。

### 谈谈 CSS 布局中 Flex 和 Grid 的使用场景

Flex 是一维布局系统，侧重于轴线上的空间分配；Grid 是二维布局系统，侧重于行和列的网格划分。

### 浏览器本地存储有哪些方式？AI聊天记录适合存哪？

常见的存储方式有 LocalStorage、SessionStorage、IndexedDB 和 Cookie。

- 特性对比：LocalStorage 容量约 5MB，持久化存储；IndexedDB 是非关系型数据库，容量大，支持索引。

- AI场景：聊天记录通常数据量较大且结构复杂，IndexedDB是存储历史对话的最佳选择。

- 性能考量：LocalStorage 是同步操作，存取大数据会阻塞主线程；IndexedDB 是异步操作。

- 安全性：敏感信息不应直接明文存储，需注意XSS攻击。

常见坑：

- 误用 Cookie 存储大数据导致 HTTP 请求头过大。

- 临时变量：保存 curr.next 以防断链。

- 边界条件：处理空链表或只有一个节点的链表。

### 在全栈开发中，Node.js 处理AI密集型任务有哪些优劣势？如何优化？

Node.js 适合处理 I/O 密集型任务，但在处理复杂的 AI 数据预处理（计算密集型）时存在瓶颈。

- 优势：异步非阻塞I/O适合处理大量并发的API请求；生态丰富，易于与前端共用代码。

- 劣势：单线程模型在处理大规模向量计算或复杂加密时会阻塞事件循环。

- 优化手段：使用 Worker Threads 开启多线程计算；通过 C++ Addons 或 Rust (napi-rs) 提升性能。

- 架构建议：Node.js 仅作为 BFF 层负责鉴权、限流和协议转换，重计算逻辑交给 Python 或 Go 服务。

常见坑：

- 在主线程执行 JSON.parse 一个超大的向量数据文件。

- 内存管理不当导致长连接场景下的 OOM。

#### 6. 技术视野：谈谈 WebAssembly（Wasm）在浏览器端运行小模型的看法。

端侧AI是未来的重要趋势，Wasm为浏览器提供了接近原生的执行性能。

- 优势：保护隐私（数据不离端）、减少服务器成本、离线可用、极低延迟。

- 现状：目前已能流畅运行轻量级的文本分类、图像分割或简单的 Embedding 模型。

- 局限性：浏览器内存限制（通常4GB）、缺乏对GPU的深度优化（期待WebGPU普及）。

- 应用场景：实时翻译、敏感词本地过滤、文档本地摘要。

常见坑：

- 忽略了模型文件下载带来的首屏加载压力。

- Wasm 与 JS 通信的开销在频繁调用时不可忽视。
