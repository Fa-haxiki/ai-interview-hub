### 说一下事件循环（Event Loop）的机制，微任务和宏任务的执行顺序是怎样的？

- 难度：中等

- 考点：JS异步运行机制、执行栈

- 答案要点:

核心机制：JS是单线程的，同步代码在主线程（执行栈）执行。异步任务被分为宏任务（MacroTask）和微任务（MicroTask）。

执行顺序：

i. 执行主线程中的同步代码。

ii. 清空当前的微任务队列（所有微任务依次执行）。

iii. 尝试进行 UI 渲染（如果需要）。

iv. 执行一个宏任务。

v. 回到第2步，循环往复。

分类：

- 微任务：Promise.then/catch/finally、MutationObserver、process.nextTick (Node.js)。

宏任务：setTimeout、setInterval、setImmediate (Node.js)、I/O、UI Rendering、MessageChannel。

### React 中 key 的作用是什么？如果用 index 作为 key 会有什么问题？

- 难度：中等

- 考点：Virtual DOM、Diff算法

- 答案要点:

- 作用：Key 是虚拟 DOM 对象的唯一标识。在 Diff 算法中，React 依靠 Key 来判断节点是被复用、修改、还是删除/新增，从而提高更新效率。

- Index 作为 Key 的问题:

i. 性能损耗：如果列表顺序发生变化（如在头部插入），所有节点的 index 都会变，React 会认为所有组件都变了，导致不必要的全量更新。

ii. 状态错乱：如果列表项中有非受控组件（如 input 输入框），复用节点时会保留旧的 DOM 状态，导致输入框内容对应错误。

### 手写实现一个 Promise.all 方法。

Promise.all 接收一个 Promise 数组，当所有 Promise 都成功时返回结果数组，只要有一个失败就立即拒绝。

- 计数器：需要一个变量记录已完成的 Promise 数量。

- 结果存储：创建一个数组，按输入顺序存储每个 Promise 的 resolve 结果。

- 状态处理：遍历输入数组，对每个项调用 Promise.resolve，并在 then 中累加计数。

- 边界条件：处理空数组的情况，应立即返回一个 resolve（）。

```javascript
function myPromiseAll(promises) {
    return new Promise((resolve, reject) => {
    if (!Array.isArray(promises)) {
    return reject(new TypeError("Argument must be an array"));
    }
    let results = [];
    let count = 0;
    const len = promises.length;

    if (len === 0) {
    return resolve([]);
    }

    promises.forEach((p, index) => {
    // 使用 Promise.resolve 兼容非 Promise 值Promise.resolve(p).then(
    (value) => {
    results[index] = value; // 保证结果顺序和输入顺序一致
    count++;
    if (count === len) {
    resolve(results);
    }
    },
    (reason) => {
    reject(reason); // 只要有一个失败，整体立即失败
    }
    );
    });
    });
    }
}
```

#### 7. 数组转树形结构

- 难度：中等

- 答案要点:

思路: 利用 Map 对象（或对象哈希）存储所有节点引用，通过一次遍历将节点挂载到其 parentId 对应的 children 数组中。时间复杂度为 \$O(n)\$。

- 代码实现：

#### JavaScript

```javascript
function arrayToTree(items) {
    const result = []; // 存放根节点const itemMap = {}; // 存放 id -> 节点的映射// 1. 先把所有项转为 Map 存储，并初始化 childrenfor (const item of items) {
    itemMap[item.id] = { ...item, children: [] };
    }
    // 2. 再次遍历，组装树for (const item of items) {
    const id = item.id;
    const pid = item.parentId;
    const treeItem = itemMap[id];
    if (pid === 0 || !itemMap[pid]) {
    // 根节点（假设0是根或找不到父节点）
    result.push(treeItem);
    } else {
    // 非根节点，挂载到父节点下
    itemMap[pid].children.push(treeItem);
    }
    }
    return result;
}
```

### 谈谈浏览器的强缓存和协商缓存。

#### - 难度：中等

- 考点：HTTP缓存机制

#### - 答案要点:

强缓存（不需要请求服务器）：

- 浏览器判断本地缓存未过期，直接读取，状态码 200 (from memory/disk cache)。

字段：Cache-Control: max-age=3600 (优先级高，HTTP/1.1)，Expires (HTTP/1.0)。

#### - 协商缓存（需要请求服务器）：

强缓存失效后，浏览器携带缓存标识向服务器发起请求，服务器判断文件是否更新。

■ 未更新：返回 304 Not Modified，继续使用本地缓存。

已更新：返回200和新内容。

字段：ETag / If-None-Match (优先级高，基于内容哈希)，Last-Modified / If-Modified-Since (基于时间)。

### TypeScript 中的 interface 和 type 有什么区别?

- 难度：简单

- 考点：TS 基础

- 答案要点:

- 相同点：都可以描述对象或函数签名，都支持扩展（extends 或 &）。

。 不同点：

i. Interface：支持声明合并（Declaration Merging），即定义同名 interface 会自动合并属性（适合写第三方库）。更侧重于面向对象接口。

ii. Type：支持基本类型别名、联合类型（Union Types |）、元组。不能重复声明。

最佳实践：编写库或定义对象形状时优先用 Interface，定义复杂关系（如 Utility Types）或联合类型时用 Type。

### 谈谈JS中的深拷贝和浅拷贝，如何实现一个深拷贝？

- 难度：中等

#### - 答案要点：

浅拷贝：只拷贝对象的第一层属性，如果属性是引用类型，拷贝的是内存地址（如Object.assign, ... 扩展运算符）。

深拷贝：递归拷贝所有层级，新旧对象互不影响。

- 简单实现：JSON.parse(JSON.stringify(obj))。缺点：无法处理函数、undefined、Symbol、Date（变字符串）、循环引用。

#### - 手写 DeepClone 要点:

i. 判断类型，如果是基本类型直接返回。

ii. 处理数组和对象。

iii. 关键：使用 WeakMap 记录已拷贝的对象，解决循环引用问题。

iv. （进阶）处理 Date, RegExp, Map, Set 等特殊类型。

#### JavaScript

```javascript
function deepClone(obj, hash = new WeakMap()) {
    if (obj === null || typeof obj != 'object') return obj;
    if (obj instanceof Date) return new Date(obj);
    if (obj instanceof RegExp) return new RegExp(obj);

    // 查表，解决循环引用if (hash.has(obj)) return hash.get(obj);

    // 获取构造函数，保留原型链，同时支持 Array 和 Objectconst cloneObj = new obj.constructor();
    hash.set(obj, cloneObj);

    for (let key in obj) {
    if (obj.hasOwnProperty(key)) {
    cloneObj[key] = deepClone(obj[key], hash);
    }
    }
    return cloneObj;
}
```

### React Fiber 架构解决了什么问题？它的工作原理是怎样的？

Fiber是React16引入的一种新的协调引擎，主要为了解决大型应用在更新时的掉帧卡顿问题。

- 核心问题：旧日的 Stack Reconciler 是递归同步执行的，一旦开始无法中断，会阻塞主线程。

- 任务拆分：Fiber将更新过程拆分成多个微小的任务单元。

- 可中断与恢复：利用requestIdleCallback机制，在浏览器空闲时执行任务，如果有高优先级任务（如输入）则中断。

- 双缓存技术：在内存中构建一棵 workInProgress 树，完成后一次性提交到真实 DOM。

#### 常见坑：

- 认为 Fiber 提高了计算速度（实际上增加了计算量，但提高了响应性）。

### 手写题：实现一个带并发限制的异步调度器 Scheduler。

思路：维护一个 queue 队列和一个计数器 count。当 count < max 时，出队执行，count++；任务完成后 count-- 并尝试执行下一个任务。

JavaScript

```javascript
class Scheduler {
    constructor(limit) {
    this.limit = limit;
    this.count = 0;
    this.queue = [];
    }
    add(promiseCreator) {
    return new Promise((resolve, reject) => {
    // 将任务包装，为了能在执行时 resolve 外部的 promiseconst task = () => {
    this.count++;
    promiseCreator()
    .then(resolve)
    .catch(reject)
    .finally(() => {
    this.count--;
    this.run(); // 任务完成，尝试调度下一个
    });
    };
    this.queue.push(task);
    this.run();
    });
    }
    run() {
    if (this.count < this.limit && this.queue.length > 0) {
    const task = this.queue.shift();
    task();
    }
    }
```

### 谈谈 Canvas 和 SVG 的区别，在 Agent 的工作流（Workflow）画布中你会选哪个？

#### - 区别:

- SVG：基于DOM，矢量图，支持事件处理器，放大不失真。适合节点数量较少（<1000）、交互复杂的情况。

- Canvas：位图，基于像素，高性能，适合成千上万个节点。缺点是事件处理麻烦（需要自己算坐标碰撞）。

#### 选型：

如果 Agent 工作流比较简单（几十个节点），首选 SVG（如使用 React Flow 库），开发效率高，CSS 定制样式容易。

如果需要展示超复杂的大规模编排（如 AI 模型层级图，上万节点），选 Canvas（如 AntV X6 或 G6 的 Canvas 模式）。

### 什么是 Service Worker? 它能为 Agent 应用带来什么提升?

- 定义：运行在浏览器后台的脚本，独立于网页，充当网络代理。

#### - Agent 场景价值:

a. 离线访问：缓存 HTML/CSS/JS shell，即使断网也能打开 APP 查看历史消息。

b. 请求拦截与缓存：缓存大型的模型配置或静态资源。

c. 后台同步 (Background Sync): 在用户网络不稳时发送的消息，可以在后台等待网络恢复后自动发送，无需用户停留在页面。

#### 三面（架构与综合能力）

### 如果让你从零设计一个 Agent 智能体平台的前端架构，你会考虑哪些核心模块？

这是一道系统设计题，建议画图或分层阐述：

1. 视图层(View Layer):

Chat UI：流式渲染器、多模态消息展示（图表、Markdown、Code）。

- Canvas Editor：工作流编排器（拖拽、连线）。

2. 逻辑控制层 (Controller/Store):

- Session Manager：管理多会话状态、上下文切换。

- SSE/WebSocket Handler：统一处理流式连接、重连、心跳、断点续传。

- Plugin System：设计插件机制，允许业务方注入自定义渲染组件（例如：股票卡片、天气卡片）。

3. 数据层 (Data Layer):

- IndexedDB：存储海量聊天记录（LocalStorage 不够用）。

- Vector Cache：如果前端做轻量级 RAG，可能需要缓存部分向量数据。

4. 基础设施 (Infra):

BFF (Backend for Frontend): 处理跨域、鉴权、流转换。

- Observability：全链路埋点（监控 Token 耗时、首字时间）。

### 在 Agent 项目中，前端如何参与 Prompt Engineering（提示词工程）的优化？

前端不仅仅是展示，还能辅助 Prompt 调优：

1. 可视化 Prompt 编排：开发“结构化 Prompt 编辑器”，将 System Prompt、Few-Shot Examples、User Input 模块化，方便非技术人员（PM/运营）调试。

2. 上下文注入 (Context Injection): 前端收集用户环境信息（当前页面 URL、选中的文本、操作系统、时区），自动拼接进 Prompt，让 AI 回答更精准。

3. A/B Testing 平台：前端配合后端实现 Prompt 的灰度发布。同一问题，A 组用 Prompt V1，B 组用 V2，通过前端埋点（点赞/点踩/留存时长）评估 Prompt 质量。
