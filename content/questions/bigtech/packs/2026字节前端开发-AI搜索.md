### 请简述一下从输入 URL 到页面渲染完成的整个过程。

这是一个经典的浏览器工作流问题，涵盖了网络请求、解析、构建树和绘制四个阶段。

- 网络阶段：DNS 解析、TCP 三次握手、TLS 协商、发送 HTTP 请求。

- 解析阶段：浏览器解析 HTML 构建 DOM 树，解析 CSS 构建 CSSOM 树。

- 渲染阶段：合并生成 Render Tree，进行 Layout（布局）计算元素几何信息。

- 绘制阶段：进行 Layering（分层）和 Painting（绘制），最后由 GPU 组合位图显示在屏幕上。常见坑：

- 忽略了DNS缓存和强缓存/协商缓存的处理逻辑。

### 在 AI 搜索场景中，流式输出（Streaming）很常见，请问前端实现流式传输有哪些方案？

流式传输主要用于实时显示大模型的生成结果，目前主流方案是 SSE 和 Fetch 的 ReadableStream。

- SSE (Server-Sent Events): 基于 HTTP 协议，服务器向客户端单向推送，支持自动重连。

- Fetch + ReadableStream：利用 Fetch API 获取 Response 对象的 body 流，通过 Reader 逐块读取。

- WebSocket：全双工通信，适合需要频繁双向交互的场景，但协议开销相对较大。

- 差异对比：SSE 简单且自带重连，Fetch 更符合现代异步编程习惯，WebSocket 适合复杂交互。常见坑：

- 混淆了SSE和长轮询的区别。

- 忽略了流式数据在前端解析时的编码问题（如 UTF-8 截断）。

### 说一下 JS 的事件循环（Event Loop）机制，宏任务和微任务的区别是什么？

JS是单线程的，通过事件循环机制来处理异步操作，确保非阻塞执行。

- 执行顺序：先执行同步代码，再清空微任务队列，最后取出一个宏任务执行，循环往复。

- 微任务（Microtask）：Promise.then、MutationObserver、process.nextTick。

- 宏任务（Macrotask）：setTimeout、setInterval、I/O、UI Rendering。

- 渲染时机：浏览器通常在每一轮宏任务执行完毕后、下一轮宏任务开始前尝试进行页面渲染。常见坑：

- 认为 async/await 是宏任务，实际上 await 之后的内容会被放入微任务。

- 混淆了 Promise 构造函数（同步）和 .then（微任务）。

### 请手写一个简单的防抖（debounce）函数，并说明它在搜索框场景下的作用。

防抖是指在事件触发后延迟一定时间执行，如果在此期间再次触发，则重新计时。

- 核心逻辑：利用闭包保存 timer 变量，每次执行前先 clearTimeout。

- 搜索场景：防止用户在输入搜索词时，每敲一个字符就发一次API请求，节省服务器资源。

- 立即执行：可选参数支持第一次触发时是否立即执行。

- 取消功能：支持手动取消尚未执行的延迟任务。

常见坑：

- 忘记处理 this 指向和 arguments 参数传递。

- 没有考虑内存泄漏（未清理定时器）。

追问：

- 节流（throttle）和防抖的区别是什么？

- 在 AI 实时搜索建议中，你会选择哪种方案？

```javascript
function debounce(fn, delay) {
    let timer = null;
    return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
    fn.apply(this, args);
    }, delay);
    };
}
```

### CSS 如何实现一个打字机效果（Typewriter Effect）？

打字机效果通常用于 AI 回答的视觉呈现，可以通过 CSS 动画或 JS 模拟实现。

### 给定一个字符串，请编写一个函数判断其中的括号（(), [], {}）是否合法闭合。

这是一个典型的栈应用题，通过遍历字符串并利用栈的后进先出特性进行匹配。

- 算法流程：遇到左括号入栈，遇到右括号则判断栈顶是否匹配，不匹配或栈为空则非法。

- 结束检查：遍历完成后，如果栈为空则说明全部匹配成功。

- 优化：使用Map存储括号的对应关系，提高代码可读性。

- 忽略了字符串中可能包含非括号字符的情况。

- 忘记在循环结束后检查栈是否为空。

- 时间复杂度和空间复杂度是多少？

```javascript
function isValid(s) {
    const stack = [];
    const map = { ')': '(', ' ]': '[', '}': '{' };
    for (let char of s) {
    if (['(', ' $$', '{}].includes(char)) {
    stack.push(char);
    } else if (map[char]) {
    if (stack.pop() !== map[char]) return false;
    }
    }
    return stack.length === 0;
}
```

### React 的 Fiber 架构解决了什么问题？它的工作原理是怎样的？

Fiber 是 React 16 引入的重构架构，旨在解决大型应用在更新时的卡顿问题。

- 核心问题：旧版 Stack Reconciler 递归更新不可中断，导致主线程长时间占用，造成掉帧。

- 解决方式：将更新任务拆分为微小的 Unit of Work（Fiber 节点），支持任务的优先级、中断与恢复。

- 双缓存技术：维护 current 树和 workInProgress 树，在内存中完成计算后一次性提交。

- 调度阶段：分为Render阶段（可中断，计算Diff）和Commit阶段（不可中断，操作DOM）。常见坑：

- 认为Fiber提高了Diff算法本身的执行速度（实际上是为了提高响应性）。

- 混淆了 Fiber 节点和真实 DOM 节点的关系。

### 在 AI 搜索结果页中，如果返回的 Markdown 内容非常长且包含大量公式、代码块，如何优化渲染性能？

长文档渲染的压力在于 DOM 节点过多和复杂的解析计算。

- 虚拟滚动：仅渲染可视区域内的 Markdown 块，减少 DOM 节点数量。

- 异步解析：利用Web Worker解析Markdown和LaTeX公式，避免阻塞主线程。

- 增量渲染：配合流式输出，解析一段渲染一段，而不是等待全部返回。

- 缓存机制：对已经解析过的代码块或公式进行结果缓存。

常见坑：

- 在主线程进行大规模的正则匹配或 AST 转换。

- 频繁触发重排（Layout），没有做DOM的批量更新。

### 你们项目中是如何处理 AI 生成内容的流式展示与自动滚动逻辑的？

自动滚动是 AI 聊天界面的核心体验，需要平衡“自动跟随”和“用户手动干预”。

- 滚动判断：在内容更新前，判断滚动条是否处于底部（设置一个阈值）。

- 自动触发：如果用户处于底部，则在 DOM 更新后调用 element.scrollIntoView({ behavior: 'smooth' })。

- 暂停机制：如果用户手动向上滚动，则停止自动滚动，并显示“回到最新”按钮。

- 性能：使用 requestAnimationFrame 优化滚动频率，避免频繁触发 Layout。常见坑：

- 无论用户是否在查看历史记录，都强制滚动到底部，导致用户无法阅读。

- 滚动动画与流式文字出现的频率不匹配，导致视觉抖动。追问：

### 浏览器跨域问题的本质是什么？在 AI 搜索开发中，你是如何解决跨域问题的？

跨域是浏览器出于安全考虑限制脚本读取非同源资源的机制。

- 本质：同源策略（协议、域名、端口必须一致），防止CSRF等攻击。

- CORS方案：最常用，服务端设置 Access-Control-Allow-Origin 等响应头。

- Proxy 代理：开发环境下使用 Vite/Webpack 的 proxy 配置，生产环境使用 Nginx 反向代理。

- 特殊场景：如果调用第三方AI接口，通常由后端中转，避免API Key暴露在前端。

- 简单请求和复杂请求（预检请求 OPTIONS）的区别没搞清楚。

- 线上环境忘记配置 Nginx 导致接口 403。

优化打包体积可以加快首屏加载速度，提升 AI 搜索的响应感。

#### 8. 请实现一个并发控制函数，要求：接收一个请求数组和最大并发数，返回所有请求结果。

在 AI 应用中，可能需要同时发起多个向量检索或图片生成请求，必须控制并发以防浏览器卡死。

- 核心思路：维护一个当前正在执行的任务计数器，当任务完成时，自动从队列中取下一个任务。

- 结果顺序：需要保证返回的结果数组顺序与请求数组一致。

- 递归/循环：可以使用递归调用或 while 循环配合 Promise.race 实现。常见坑：

- 无法处理请求失败的情况，导致整个 Promise 挂起。

- 结果数组的索引处理错误。

追问：

- 如果其中一个请求超时了，如何处理？

```javascript
async function limitConcurrency(tasks, limit) {
    const results = [];
    const executing = [];
    for (const task of tasks) {
    const p = Promise.resolve().then(() => task());
    results.push(p);
    if (limit <= tasks.length) {
    const e = p.then(() => executing.splice(executing.indexOf(e), 1));
    executing.push(e);
    if (executing.length >= limit) {
    await Promise.race(executing);
    }
    }
    }
    return Promise.all(results);
}
```

AI工具改变了代码编写方式，但前端的核心价值正在从“写代码”转向“设计系统”。

### 在团队协作中，如果后端接口定义的格式与前端需求严重不符，且后端不愿修改，你会如何处理？

这是典型的协作冲突场景，应本着业务目标优先的原则寻找折中方案。

- 推动规范：如果该格式影响了多个页面或性能，应整理数据对比，在技术评审会上提出，推动长期规范的制定。

- 权衡利弊：如果是短期项目，前端承担转换逻辑；如果是长期项目，坚持推动后端优化以保证系统简洁。

常见坑：

- 情绪化沟通，导致协作关系僵化。

- 默默在业务代码中写满 if-else 转换，导致代码腐烂。
