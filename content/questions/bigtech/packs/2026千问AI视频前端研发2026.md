#### 2. 谈谈你对 JavaScript 闭包的理解。

### 谈谈你对 JavaScript 闭包的理解。

闭包是指有权访问另一个函数作用域中变量的函数，本质是函数与其词法环境的引用捆绑在一起。

- 形成条件：函数嵌套且内部函数引用了外部函数的变量。

- 核心作用：实现数据的私有化，防止全局变量污染，常用于模块化封装。

- 内存影响：由于内部函数持有外部变量引用，会导致相关变量无法被垃圾回收机制自动回收。

- 实际应用：在高阶函数、柯里化、防抖节流函数中广泛使用。

- 在循环中创建闭包未注意变量捕获时机。

- 滥用闭包导致内存泄漏。

### Promise 有哪几种状态？async/await 和它是什么关系？

Promise 是异步编程的一种解决方案，包含 Pending、Fulfilled 和 Rejected 三种状态，状态一旦改变不可逆。

### 介绍一下浏览器的事件循环（Event Loop）机制。

事件循环是JavaScript处理异步任务的核心机制，通过任务队列协调主线程的执行顺序。

- 任务分类：分为宏任务（setTimeout, script）和微任务（Promise.then, MutationObserver）。

- 执行顺序：执行一个宏任务 -> 清空所有微任务 -> 渲染页面 -> 执行下一个宏任务。

- 渲染时机：微任务清空后、宏任务执行前是浏览器尝试更新 UI 的时机。

- 阻塞后果：主线程长任务会阻塞事件循环，导致页面卡顿。常见坑：

- 认为setTimeout(fn, 0)会立即执行。

- 混淆了 Node.js 和浏览器的事件循环差异。

#### 1. React 的 Fiber 架构解决了什么问题？它的工作原理是什么？

### React的Fiber架构解决了什么问题？它的工作原理是什么？

Fiber 架构主要解决了 React 在处理复杂组件树时，长任务阻塞主线程导致页面卡顿的问题。

- 核心目标：实现增量渲染，将渲染工作拆分为多个小任务，支持任务的优先级和中断。

- 数据结构：Fiber 是一个链表结构，记录了组件的类型、DOM 节点及兄弟/子节点引用。

- 两个阶段：Render 阶段（可中断，计算差异）和 Commit 阶段（不可中断，同步更新 DOM）。

- 调度器：通过 Scheduler 调度任务，利用浏览器空闲时间（requestIdleCallback 思想）执行。
常见坑：

- 误以为Fiber是为了提高渲染绝对速度（实际上是为了提高响应性）。

- 在Render阶段执行具有副作用的操作。

- 最后一个分片上传完成后，合并请求的超时处理。

- 开发环境与生产环境行为不一致（ESM vs Rollup）。

### 手写代码：实现一个简单的 Promise.all。

Promise.all 接收一个 Promise 数组，返回一个新的 Promise，要求所有任务都成功才成功。

- 计数器：维护一个 count 变量记录已完成的任务数。

- 结果存储：创建一个结果数组，按输入顺序存放 resolve 的值。

- 失败处理：只要有一个任务 reject，整体立即 reject。

- 边界处理：处理输入为空数组的情况。

代码示例：

```javascript
1 Promise.myAll = function(promises) {
2    return new Promise((resolve, reject) => {
3    let count = 0;
4    const results = [];
5    if (promises.length === 0) return resolve([]);
6    promises.forEach((p, i) => {
7    Promise.resolve(p).then(res => {
8    results[i] = res;
9    count++;
10    if (count === promises.length) resolve(results);
11    }, reject);
12    });
13    });
14 };
```

- 轮询机制：对于超长任务，前端发起任务后，通过短轮询或 WebSocket 监听进度。

- 体验优化：展示进度条、预计剩余时间，或提供“后台生成”选项。

- 容错重连：接口报错时实施指数退避算法的自动重试。

常见坑：

- 超时时间设置过短，导致大模型还没计算完就被前端切断。

- 界面无反馈，让用户以为页面挂掉了。

### 如果让你从零设计一个AI视频编辑器前端架构，你会考虑哪些核心模块？

### 前端如何利用 AI 提升研发效率？谈谈你的实践或思考。

#### 3. 在 AI 视频产品中，如何解决模型生成结果不确定性带来的 UI 挑战？

### 在 AI 视频产品中，如何解决模型生成结果不确定性带来的 UI 挑战？

AI 生成具有随机性，前端需要通过设计手段引导用户并处理异常结果。

- 结果预览：提供多版本并行生成预览，让用户进行对比选择（A/B 选优）。

- 参数约束：通过前端表单校验和滑块限制，将模型参数控制在易出好结果的范围内。

- 状态反馈：细化生成步骤（如：理解需求中、绘制草图、渲染视频），缓解用户焦虑。

- 兜底策略：当生成失败或内容违规时，提供清晰的错误提示及重试建议。

- 界面只显示一个 Loading，用户不知道当前 AI 处理到了哪一步。

- 未处理 AI 返回的非法格式数据导致页面白屏。

### 如何设计一个通用的 AI Agent 配置化组件?

Agent 组件需要具备高度的可扩展性，以适配不同能力的模型和工具调用。

#### 6. 谈谈你对 WebGPU 的看法，它会对 AI 视频前端开发带来什么改变？

### 谈谈你对WebGPU的看法，它会对AI视频前端开发带来什么改变？

WebGPU 是下一代 Web 图形标准，提供了比 WebGL 更直接的 GPU 访问能力。

- 计算能力：支持 Compute Shader，使得在前端进行大规模并行计算（如视频转码、AI推理）成为可能。

- 性能飞跃：减少了CPU到GPU的通信开销，渲染复杂视频特效时帧率更稳定。

- 端侧 AI：配合 Transformers.js 等库，可以在浏览器端直接运行小型模型，减少服务器压力。

- 行业趋势：是未来高性能Web应用（编辑器、游戏、AI工具）的核心基石。常见坑：

- 忽略了目前WebGPU尚不完美的兼容性。

- 学习曲线陡峭，对开发者的图形学基础要求较高。

#### 7. 如果项目需要支持多语言（国际化），在 AI 视频场景下有哪些特殊考虑？

### 如果项目需要支持多语言（国际化），在AI视频场景下有哪些特殊考虑？

除了基础的文本翻译，AI视频产品还涉及音视频同步和文化差异。

- 语音对齐：AI生成的配音在不同语言下长度不同，前端需动态调整视频帧或字幕时间轴。

- 字体支持：视频渲染引擎需支持多国语言字体，防止出现方块字。

- 布局自适应：处理RTL（从右向左）语言对UI布局的影响。

- 敏感词库：不同国家对 AI 生成内容的合规性要求不同，前端需配合做差异化过滤。常见坑：

- 硬编码了视频中的文字，导致无法翻译。

- 忽略了数字、日期格式在不同国家的展示习惯。
