### 简单介绍一下 SSE 和 WebSocket 的区别，为什么 AI 聊天场景多用 SSE?

SSE 是基于 HTTP 的单向推送协议，而 WebSocket 是全双工的独立协议。在 AI 问答场景中，服务端需要持续输出 Token，SSE 更加轻量且天然支持 HTTP 协议。

- 协议类型：SSE是HTTP协议，WebSocket是独立协议

- 数据流向：SSE仅支持服务端向客户端推送，WebSocket支持双向通信

- 重连机制：SSE 内置断线重连，WebSocket 需要手动实现

- 场景适配：AI场景主要是服务端单向输出，SSE的开销更小且兼容性好常见坑：

### 说一下 Promise.all 和 Promise.allSettled 的区别，AI 多模型并行调用时选哪个？

Promise.all 要求全部成功，而 Promise.allSettled 会等待所有结果。在调用多个 AI 模型对比结果时，通常使用 allSettled 以保证部分模型失败不影响整体展示。

- 状态处理：all 在任一失败时立即 reject，allSettled 永远 resolve

- 返回值结构：allSettled 返回包含 status 和 value/reason 的对象数组

- 容错性：allSettled更适合相互独立的任务并行

- 场景选择：AI并行对比、多插件加载建议使用allSettled常见坑：

- 在 allSettled 的结果中忘记判断 status 导致访问 value 报错

### 手写题：实现一个简单的防抖函数（Debounce），并说明在 AI 搜索建议中如何应用。

防抖函数用于在事件触发后延迟执行，如果在延迟时间内再次触发则重新计时。在 AI 搜索建议中，可以减少不必要的 API 调用。

- 核心逻辑：利用闭包存储 timer，每次触发先clearTimeout

- 参数传递：确保 this 指向和 arguments 正确传递

- 应用场景：输入框实时搜索、窗口大小调整

- AI 关联：用户输入 Prompt 过程中，等待停顿后再请求 AI 进行补全建议常见坑：

- 忘记返回函数

- 闭包变量 timer 污染全局

代码示例：

```javascript
1 function debounce(fn, delay) {
2    let timer = null;
3    return function(...args) {
4    if (timer) clearTimeout(timer);
5    timer = setTimeout(() => {
6    fn.apply(this, args);
7    }, delay);
8    }
9 }
```

### React 的 Fiber 架构是如何提升复杂 AI 应用性能的？

Fiber将渲染工作拆分为小单元，支持任务优先级和中断。在AI应用中，当流式输出大量文本导致DOM压力大时，Fiber能保证UI响应不卡顿。

- 核心机制：时间分片（Time Slicing）与增量渲染

- 双缓存技术：在内存中构建Fiber树，减少直接操作DOM的开销

- 协调过程：Reconciliation 阶段可中断，Commit 阶段同步执行常见坑：

### 如何优化 AI 流式输出时的 Token 渲染频率，避免过度消耗 CPU?

AI 输出速度可能极快，如果每个 Token 都触发一次 React 渲染，会导致严重的性能抖动。

- 策略一：缓冲区机制。将收到的 Token 先存入队列，按固定频率（如 60ms）批量更新状态

- 策略二：RequestAnimationFrame。配合浏览器刷新率进行 UI 更新

- 策略三：局部渲染。仅对最后一个消息组件进行增量更新，避免父组件重绘

- 策略四：离屏渲染。对于复杂的 Markdown 或公式，先在内存中解析

- 在循环中直接调用 setState

- 忽略了后台标签页时定时器变慢的问题
