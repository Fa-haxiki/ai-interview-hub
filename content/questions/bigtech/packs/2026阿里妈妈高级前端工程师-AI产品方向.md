### 简单介绍一下 Promise 的状态机机制，以及 all 和 allSettled 的区别。

Promise 是异步编程的一种解决方案，它有三种状态：pending、fulfilled 和 rejected，状态切换不可逆。

- 状态转换：只能从 pending 变为 fulfilled 或从 pending 变为 rejected。

- Promise.all: 接收一个 Promise 数组，只有全部成功才返回成功结果数组，只要有一个失败就立即返回失败。

- Promise.allSettled：无论每个Promise成功还是失败，都会等待所有Promise完成，并返回包含每个结果状态的对象数组。

- 适用场景：all适用于强依赖关系的并行请求，allSettled适用于互不影响的独立任务。常见坑：

- 忽略 Promise.all 的短路特性，导致部分逻辑未执行。

- 在 allSettled 中忘记判断 status 字段直接取值。

#### 2. 在 AI 对话场景中，流式输出通常使用 SSE 协议，它和 WebSocket 有什么区别？

### 在AI对话场景中，流式输出通常使用SSE协议，它和WebSocket有什么区别？

SSE（Server-Sent Events）是基于 HTTP 的单向通信协议，允许服务器向客户端推送数据，非常适合 AI 逐字生成的场景。

- 通信方向：SSE是单向的（服务端到客户端），WebSocket是全双工的双向通信。

- 协议基础：SSE基于标准HTTP协议，无需握手升级，WebSocket需要独立的协议转换。

- 断线重连：SSE 内置了自动重连机制，WebSocket 需要开发者手动实现。

- 数据格式：SSE 默认传输文本（UTF-8），WebSocket 支持二进制和文本。

- SSE 在 HTTP/1.1 下有浏览器连接数限制（通常为 6 个），需升级 HTTP/2。

- 忽略了SSE的数据缓冲区问题，导致前端无法实时接收到“流”。

### 说一下TypeScript中interface和type的区别，以及在AI参数定义中如何选择？

interface 主要用于定义对象的结构，支持声明合并；type 则是类型别名，支持联合类型、元组等更复杂的定义。

- 扩展方式：interface 通过 extends 继承，type 通过 & 交叉类型实现。

- 声明合并：同名 interface 会自动合并，type 不允许同名定义。

- 适用场景：定义 AI 插件的配置接口建议用 interface，定义模型名称（如 'gpt-3.5' | 'gpt-4'）建议用 type。

- 性能：interface 的类型检查性能通常略优于 type。

常见坑：

- 忽略了interface自动合并可能带来的全局污染。

#### 5. 手写题：实现一个简单的防抖函数（debounce）。

### 手写题：实现一个简单的防抖函数（debounce）。

防抖是指在事件被触发 n 秒后再执行回调，如果在这 n 秒内又被触发，则重新计时。

- 核心原理：利用闭包保存 timer 变量。

- 清除定时器：每次触发时先clearTimeout。

- 立即执行：可选参数支持第一次触发时是否立即执行。

- 返回值：确保 this 指向和参数正确传递。

```javascript
function debounce(fn, delay) {
    let timer = null;
    return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
    fn.apply(this, args);
    }, delay);
    };
}
```

#### 常见坑：

- 忘记处理 this 指向。

- 忘记处理arguments参数。

#### 1. React 的 Fiber 架构解决了什么问题？在 AI 长文本渲染中有什么优势？

### React 的 Fiber 架构解决了什么问题？在 AI 长文本渲染中有什么优势？

Fiber 架构通过将渲染工作拆分为小片并支持优先级调度，解决了 React 在处理大量 DOM 更新时的掉帧问题。

- 核心机制：引入了可中断的异步渲染，将同步更新变为增量更新。

- 调度器（Scheduler）：根据任务优先级（如用户输入高于数据流更新）决定执行顺序。

- AI场景优势：AI流式返回时，频繁的state更新不会阻塞UI响应，保证了用户输入的流畅性。

- 双缓存技术：在内存中构建Fiber树，减少了直接操作真实DOM的开销。

- 误以为Fiber提高了渲染绝对速度，实际上它提升的是感知流畅度。

- 在 render 阶段执行了有副作用的操作。

8. 手写题：实现一个并发控制函数，要求同时最多执行 3 个异步任务。

### 手写题：实现一个并发控制函数，要求同时最多执行3个异步任务。

核心思路是维护一个正在执行的任务队列，当一个任务完成后，自动触发下一个任务。

- 计数器：记录当前正在运行的任务数。

- 任务队列：存储待执行的任务。

- 递归执行：任务完成后，计数器减一，并从队列中取新任务执行。

```javascript
async function limitConcurrency(tasks, limit) {
    const results = [];
    const executing = new Set();
    for (const task of tasks) {
    const p = Promise.resolve().then(() => task());
    results.push(p);
    executing.add(p);
    const clean = () => executing.delete(p);
    p.then(clean).catch(clean);
    if (executing.size >= limit) {
    await Promise.race(executing);
    }
    }
    return Promise.all(results);
}
```

#### 常见坑：

- 无法正确处理任务失败的情况。

- 结果顺序与输入顺序不一致。
