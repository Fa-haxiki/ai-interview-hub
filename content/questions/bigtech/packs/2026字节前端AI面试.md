### 请简述一下 SSE（Server-Sent Events）的工作原理，它与WebSocket 有什么区别？

SSE 是一种基于 HTTP 协议的单向通信机制，允许服务器主动向客户端推送文本数据，常用于 AI 聊天的流式回复。

- 协议基础：基于标准 HTTP 协议，设置 Content-Type 为 text/event-stream。

- 连接特性：长连接，默认支持断线重连（Retry机制）。

- 数据格式：以 data: 开头的文本流，支持自定义事件类型。

- 对比 WS：SSE 是单向的（Server to Client），更轻量，支持 HTTP 代理和自动重连；WebSocket 是全双工的，更复杂。

常见坑：

- 浏览器连接数限制（Chrome 同域名限制 6 个 SSE 连接）。

- 必须处理 HTTP 2.0 以绕过连接数限制。

#### 3. 说一下 Fetch API 如何实现请求的中断？

### 说一下 Fetch API 如何实现请求的中断？

Fetch 本身不直接支持 timeout，需要通过 AbortController 信号量来手动控制请求的终止。

- 核心步骤：实例化 AbortController，将 controller.signal 传入 fetch 的 options。

- 触发中断：调用 controller.abort() 方法。

- 异常捕获：中断后 fetch 会抛出名为 AbortError 的 DOMException，需在 catch 中识别。

- 场景应用：用户点击“停止生成”按钮，或组件销毁时清理未完成的AI调用。常见坑：

- abort() 调用后，signal 状态不可逆，再次请求需 new 新实例。

#### 4. 手写题：实现一个带并发限制的 Promise 调度器

### 手写题：实现一个带并发限制的 Promise 调度器

该调度器用于控制同时进行的异步任务数量，防止在多模型调用或大量图片生成时压垮浏览器。

- 核心逻辑：维护一个运行中队列和一个等待队列。

- 递归触发：每个任务完成后，自动从等待队列中取下一个任务执行。

- 状态管理：记录当前 count，对比 limit。

```javascript
class Scheduler {
    constructor(limit) {
    this.limit = limit;
    this.count = 0;
    this.queue = [];
    }
    async add(fn) {
    if (this.count >= this.limit) {
    await new Promise(resolve => this.queue.push(resolve));
    }
    this.count++;
    const res = await fn();
    this.count--;
    if (this.queue.length > 0) {
    this.queue.shift()();
    }
    return res;
```

#### 常见坑：

- 任务失败时没有正确释放 count 导致死锁。

#### 6. JS 中的 ArrayBuffer 和 Blob 有什么区别？在处理 AI 多模态数据时怎么用？

### JS 中的 ArrayBuffer 和 Blob 有什么区别？在处理 AI 多模态数据时怎么用？

ArrayBuffer 是原始的二进制内存缓冲区，而 Blob 是不可变的类文件对象，两者在处理 AI 生成的图片或语音时非常关键。

- ArrayBuffer：代表纯数据，不能直接操作，需通过 TypedArray（如 Uint8Array）或 DataView 读写。

- Blob：通常用于存储文件数据，可以通过URL.createObjectURL转化为浏览器可识别的src。

- 转换关系：Blob 可以通过 arrayBuffer() 方法转为 Buffer，Buffer 也可以封装成 Blob。

- AI场景：语音转文字（ASR）时处理音频流用Buffer，展示生成的图片用BlobURL。常见坑：

- 忘记手动释放 URL.createObjectURL 产生的内存。

### 在 React/Vue 中渲染流式返回的Markdown文本，有哪些性能优化手段？

流式渲染会导致组件频繁重绘，优化核心在于减少解析频率和控制DOM更新范围。

- 增量解析：不要每次都解析全量文本，尝试记录已解析位置，仅对新片段进行增量处理。

- 节流渲染：通过 requestAnimationFrame 或节流函数控制渲染频率，避免每收到一个字符就 setState。

- 静态节点跳过：利用 React.memo 或 Vue 的 v-once 锁定已生成的历史对话片段。

- 插件优化：禁用 Markdown 插件中耗时较长的功能（如复杂的数学公式同步渲染）。

- Markdown 解析器（如 marked）在处理未闭合的代码块标签时可能导致页面结构崩溃。

#### 5. 如何优化 AI 应用的首字响应时间 (TTFT)?

### 如何优化 AI 应用的首字响应时间（TTFT）？

TTFT 是 AI 应用的核心指标，优化需从网络协议、后端策略和前端预判三方面入手。

- 协议优化：强制开启 HTTP/2 或 HTTP/3，减少握手耗时；使用流式传输而非全量返回。

- 预加载策略：在用户输入时预连接（dns-prefetch）模型接口域名。

- 交互欺骗：在等待首字时，立即展示 Loading 动画或占位符，减少用户焦虑。

- 边缘计算：利用 Edge Runtime（如 Vercel Edge Functions）在地理位置更近的节点处理请求。常见坑：

- 开启了 Gzip 压缩导致流式传输被缓存，必须关闭流式接口的 Gzip。

#### 6. 如果要在前端运行轻量级模型（如 Transformers.js），你会考虑哪些因素？

### 如果要在前端运行轻量级模型（如 Transformers.js），你会考虑哪些因素？

在浏览器端运行模型可以节省服务器成本并保护隐私，但面临算力和存储挑战。

- 运行环境：利用WebAssembly (WASM) 提升计算性能，使用WebGPU加速矩阵运算。

- 模型压缩：采用量化（Quantization）技术将模型缩小（如 FP32 转 INT8）。

- 缓存机制：利用 Cache Storage 存储模型权重文件，避免重复下载（通常几十 MB）。

- 线程隔离：必须在Web Worker中运行模型推理，防止阻塞主线程导致页面卡死。

常见坑：

- 浏览器内存限制导致大模型加载失败。
