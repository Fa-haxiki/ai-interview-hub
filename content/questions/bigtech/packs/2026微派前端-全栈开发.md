### 说一下 JavaScript 中的事件循环机制。

事件循环是JS处理异步任务的核心机制，通过任务队列的调度实现单线程下的非阻塞I/O。

- 执行栈：同步代码按顺序进入执行栈执行。

### Promise 有哪几种状态？如何实现一个 Promise.all?

Promise 是异步编程的一种解决方案，它有三种状态且状态转换不可逆。

- 状态：Pending（进行中）、Fulfilled（已成功）、Rejected（已失败）。

- Promise.all 逻辑：接收一个 Promise 实例数组，只有全部成功才返回结果数组，只要有一个失败就立即返回失败原因。

- 计数器机制：内部维护一个计数器，每当一个Promise完成时计数加一，直到等于数组长度。

- 结果顺序：必须保证输出数组的顺序与输入 Promise 数组的顺序一致。

- 忘记处理非 Promise 类型的输入项。

- 没能正确处理空数组的情况。

代码示例：

```javascript
function promiseAll(promises) {
    return new Promise((resolve, reject) => {
    let results = [];
    let count = 0;
    promises.forEach((p, index) => {
    Promise.resolve(p).then(res => {
    results[index] = res;
    count++;
    if (count === promises.length) resolve(results);
    }, err => reject(err));
    });
    });
}
```

### 什么是防抖和节流？请手写一个防抖函数。

防抖和节流都是为了限制高频触发事件的执行频率，但其核心逻辑和应用场景不同。

- 防抖（Debounce）：在事件触发N秒后再执行，如果N秒内再次触发，则重新计时。适用于搜索框输入。

- 节流（Throttle）：在规定时间内只执行一次，无论触发多少次。适用于滚动监听。

- 实现原理：利用闭包存储定时器变量（timer）。

常见坑：

- 忘记绑定 this 指向。

- 没能正确传递arguments参数。

代码示例：

```javascript
function debounce(fn, delay) {
    let timer = null;
    return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
    fn.apply(this, args);
    }, delay);
};
```

### TypeScript 中的 interface 和 type 有什么区别?

两者都用于定义类型，但在扩展性、合并规则和适用场景上有所不同。

- 合并能力：interface 支持声明合并（同名接口会自动合并），type 不支持。

- 类型范围：type 可以定义基本类型别名、联合类型、元组等，interface 主要用于定义对象结构。

- 扩展方式：interface 通过 extends 扩展，type 通过交叉类型（&）扩展。

- 建议：优先使用 interface 定义公共 API 的对象结构，使用 type 处理复杂的类型组合。常见坑：

### 介绍一下浏览器的强缓存和协商缓存。

浏览器缓存机制通过减少网络请求来提升页面加载速度，分为强缓存和协商缓存两个阶段。

- 强缓存：不向服务器发送请求，直接从本地读取。主要通过 Cache-Control（max-age）和 Expires 控制。

- 协商缓存：向服务器发送请求，由服务器决定是否使用缓存。主要通过 ETag/If-None-Match 和 Last-Modified/If-Modified-Since 控制。

- 优先级：Cache-Control 优先级高于 Expires；ETag 优先级高于 Last-Modified。

- 状态码：强缓存命中返回200 (from disk/memory cache)，协商缓存命中返回304。常见坑：

- 不清楚 ETag 相比 Last-Modified 的优势（如秒级内修改、内容未变但时间变了）。

- 误以为协商缓存不发请求。

### 给定一个整数数组 nums 和一个目标值 target，请找出和为目标值的两个整数的下标。

这是经典的算法题，最优解是利用哈希表将时间复杂度降低到 $O(n)$ 。

- 暴力法：双重循环，复杂度 $O(n^2)$ ，不推荐。

- 哈希表法：遍历数组，计算 target - nums[i]，检查该差值是否已在 Map 中。

- 空间换时间：利用Map存储已遍历过的数值及其下标。

代码示例：

```javascript
function twoSum(nums, target) {
    const map = new Map();
    for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (map.has(complement)) {
    return [map.get(complement), i];
    }
    map.set(nums[i], i);
    }
}
```

### 谈谈 React 的 Fiber 架构，它解决了什么问题？

Fiber是React16引入的一种新的协调引擎，旨在提高复杂应用的响应速度和流畅度。

- 核心问题：老版本 Stack Reconciler 递归执行，一旦开始无法中断，会导致主线程卡顿。

- 解决方案：将渲染工作拆分为微小的任务单元（Fiber），支持任务的暂停、恢复和优先级调度。

- 双缓存技术：维护 current 树和 workInProgress 树，在内存中构建好后一次性提交。

- 调度阶段：分为Reconcile（可中断，计算差异）和Commit（不可中断，操作DOM）。常见坑：

- 误以为Fiber提高了渲染的绝对速度（其实是提高了响应性）。

- 不清楚哪些生命周期在 Fiber 架构下会被多次触发。

### Vue 3 的响应式原理与 Vue 2 有什么区别?

Vue 3 放弃了 Object.defineProperty，改用 ES6 的 Proxy 来实现响应式系统。

- 监听粒度：Proxy可以直接监听整个对象而非属性，支持监听数组索引变化和对象属性的新增/删除。

- 性能优化：Vue 3 是延迟监听，只有访问到深层属性时才递归创建 Proxy，而 Vue 2 在初始化时就递归。

- 依赖收集：Vue3使用Effect存储依赖，通过Track和Trigger进行触发。

- 代码组织：配合Composition API，响应式逻辑更加解耦和易于复用。

- 不清楚 Proxy 无法兼容 IE 浏览器。

- 忽略了Vue3中ref和reactive的实现差异。

### Webpack 和 Vite 的构建原理有什么本质区别?

两者代表了两种不同的构建思路：Webpack 是基于 Bundle 的全量构建，而 Vite 是基于 ESM 的按需编译。

- Webpack：启动时需要递归分析依赖并打包，项目越大启动越慢；HMR也会随项目规模变大而变慢。

- Vite：开发环境下利用浏览器原生支持ESM的特性，只在请求时编译对应文件，实现秒级启动。

- 生产环境：Vite 生产环境目前仍使用 Rollup 打包，以获得更好的兼容性和 Tree Shaking。

- 预构建：Vite 使用 esbuild 对三方库进行预构建，提升加载效率。

常见坑：

- 不清楚Vite在旧版浏览器下的兼容性局限。

- 忽略了Vite在开发环境和生产环境表现不一致的风险。

### Node.js 的事件循环与浏览器有什么不同?

虽然都基于事件循环，但 Node.js 的 libuv 引擎定义了更复杂的阶段。

- 阶段划分：Node.js 分为 timers、pending callbacks、idle/prepare、poll、check、close callbacks 六个阶段。

- process.nextTick：它不属于事件循环的任何阶段，而是在每个阶段切换的间隙立即执行，优先级高于Promise。

- setImmediate vs setTimeout: setImmediate 在 check 阶段执行，setTimeout 在 timers 阶段执行。

- 宏任务/微任务：在 Node 11+ 之后，微任务的执行时机已与浏览器基本趋同。

- 混淆了 Node.js 旧版本和新版本的执行顺序差异。

- 错误理解 poll 阶段的阻塞机制。

### 如何处理前端的安全问题？(XSS, CSRF)

安全是前端开发不可忽视的一环，主要防范脚本注入和跨站请求伪造。

- XSS（跨站脚本攻击）：通过转义输入输出、使用 CSP（内容安全策略）、设置 HttpOnly Cookie 来防范。

- CSRF（跨站请求伪造）：通过验证 Referer/Origin、使用 CSRF Token、设置 SameSite Cookie 属性来防范。

- 点击劫持：使用 X-Frame-Options 响应头防止页面被嵌入 iframe。

- 依赖安全：定期扫描npm包漏洞。

常见坑：

- 混淆了 XSS 和 CSRF 的攻击原理。

### 实现一个简单的发布订阅模式（EventEmitter）。

发布订阅模式是前端非常重要的设计模式，用于解耦组件通信。

- 数据结构：使用一个对象（events）存储事件名与回调函数数组的映射。

- 核心方法：on（订阅）、emit（发布）、off（取消订阅）、once（只执行一次）。

- 细节处理：取消订阅时需要准确找到对应的函数引用。

代码示例：

```javascript
class EventEmitter {
    constructor() {
    this.events = {};
    }
    on(name, fn) {
    if (!this.events[name]) this.events[name] = [];
    this.events[name].push(fn);
    }
    emit(name, ...args) {
    if (this.events[name]) {
    this.events[name].forEach(fn => fn(...args));
    }
    }
    off(name, fn) {
    if (this.events[name]) {
    this.events[name] = this.events[name].filter(f => f !== fn);
    }
    }
}
```

提升代码质量需要从流程规范、工具约束和技术交流三个层面共同发力。

- 流程规范：强制执行 Code Review，建立清晰的 PR 审核机制。

- 工具约束：配置统一的 ESLint/Prettier 规则，利用 Git Hooks 在提交前进行自动化检查。

- 技术分享：定期举办技术分享会（Tech Talk），沉淀最佳实践文档。

- 单元测试：针对核心逻辑和公共组件编写单元测试，提高重构的信心。常见坑：

- 只有规范没有执行力。

- 规范过于严苛导致开发效率大幅下降。

### 你对全栈开发的理解是什么？在Node.js侧你主要处理过哪些业务？

全栈不仅是会写前后端代码，更重要的是具备全局视野，能从整体架构角度优化产品。

- 职责范围：API设计、数据库建模（Schema设计）、中间件开发、服务器部署与运维。

- Node.js 应用：开发 BFF 层（聚合接口）、编写自动化脚本、处理 SSR 渲染逻辑、开发内部管理工具。

- 核心关注：关注 Node.js 的内存管理、异步 I/O 性能、集群模式（PM2）以及日志追踪。

- 协作优势：全栈背景能更高效地与纯后端沟通，减少沟通成本，快速推进原型落地。常见坑：

- 只是会写简单的CRUD，对数据库索引优化、缓存策略等后端核心知识了解不足。

### 面对一个大型陈旧项目，你会如何制定重构计划？

重构大型项目必须遵循“小步快跑、不影响业务”的原则，严禁推倒重来。

- 现状分析：梳理核心链路、依赖关系，找出最影响开发效率和稳定性的痛点。

- 灰度策略：采用微前端或多页应用共存的方式，新功能用新架构，老功能逐步迁移。

- 自动化测试：在重构前先补齐核心逻辑的测试用例，确保重构后功能等价。

- 阶段性产出：将重构拆分为多个里程碑，每个阶段都要有可交付、可验证的结果。常见坑：

- 陷入重构泥潭，导致业务需求长期停滞。

- 缺乏测试保障，重构引入大量新 Bug。

### 你未来两三年的职业规划是怎样的？目前在关注哪些前沿技术？

#### 考点：自我驱动与潜力

这个问题旨在考察候选人的上进心和对技术趋势的敏感度。

- 深度与广度：在前端领域持续深挖（如性能优化、架构设计），同时向后端或跨端（Flutter/RN）扩展。

- 软实力：提升项目管理能力、团队带教能力，从技术执行者向技术负责人转变。

- 学习方法：通过阅读源码、参与开源项目、撰写技术博客来持续沉淀。常见坑：

- 回答得太泛（如“想学更多东西”），没有具体目标。

- 关注的技术与实际工作脱节太严重。
