### 聊聊 JavaScript 的事件循环机制，宏任务和微任务的执行顺序是怎样的？

事件循环是JS处理异步操作的核心机制，通过任务队列的调度实现单线程非阻塞。

- 执行栈清空后，优先处理所有微任务队列中的任务

- 微任务处理完后，取出一个宏任务执行

- 常见的宏任务包括setTimeout、setInterval、I/O

- 常见的微任务包括 Promise.then、MutationObserver、process.nextTick
常见坑：

- 误以为 await 后面的代码是宏任务，实际上 await 后的内容会被包装成微任务

### 说一下 SSE（Server-Sent Events）和 WebSocket 的区别，为什么 AI 对话场景多用 SSE?

SSE 是一种基于 HTTP 的单向推送协议，相比 WebSocket 更加轻量且原生支持断线重连。

- SSE是单向的（服务端到客户端），WebSocket是全双工双向通信

- SSE基于标准HTTP协议，对防火墙和代理服务器更友好

- AI场景下，模型生成是流式的且不需要客户端频繁反馈，SSE协议开销更小

- 认为 SSE 可以发送二进制数据（实际上主要传输文本）

- 忽略了浏览器对 HTTP/1.1 下 SSE 最大连接数的限制（通常为 6 个）

### 手写一个深拷贝函数，需要考虑循环引用和 Symbol 类型。

深拷贝需要递归遍历对象的所有属性，并处理特殊类型以及避免循环引用导致的死循环。

- 使用WeakMap存储已拷贝的对象，解决循环引用问题

- 使用 Reflect.ownKeys 获取包括 Symbol 在内的所有键名

- 区分处理数组、对象、Date、RegExp等特殊引用类型

- 递归终止条件是处理基本数据类型

常见坑：

- 使用Map而不是WeakMap导致内存无法被回收

- 忽略了 Symbol 类型的属性拷贝

代码示例：

```javascript
function deepClone(obj, hash = new WeakMap()) {
    if (obj === null || typeof obj != 'object') return obj;
    if (obj instanceof Date) return new Date(obj);
    if (obj instanceof RegExp) return new RegExp(obj);
    if (hash.has(obj)) return hash.get(obj);

    const cloneObj = new obj.constructor();
    hash.set(obj, cloneObj);

    Reflect_ownKeys(obj).forEach(key => {
    cloneObj[key] = deepClone(obj[key], hash);
    });
    return cloneObj;
}
```

### React 的 Fiber 架构解决了什么问题？它的工作原理是什么？

Fiber架构解决了React在处理大型组件树时，由于同步渲染阻塞主线程导致的掉帧问题。

- 引入了协作式调度，将渲染工作拆分为可中断的微小单元

- 分为 Reconciliation（协调）和 Commit（提交）两个阶段

- 协调阶段是可中断的，通过requestIdleCallback寻找执行时机

- 双缓存技术：在内存中构建 WorkInProgress Tree，完成后一次性切换常见坑：

- 误认为Fiber提高了渲染速度（实际上是提高了响应速度）
