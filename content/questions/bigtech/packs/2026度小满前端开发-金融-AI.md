### 简单介绍一下 Promise 的状态机机制，以及 async/await 是如何处理异步的？

Promise 是一个代表异步操作最终完成或失败的对象，其核心是一个拥有三种状态的状态机。

- 状态转换：Pending（待定）到 Fulfilled（已兑现）或 Rejected（已拒绝），状态一旦改变不可逆转。

- 链式调用：通过 .then() 和 .catch() 返回新的 Promise 实现链式操作。

- 语法糖：async/await 是 Generator 的语法糖，通过内置执行器让异步代码以同步方式书写。

- 错误捕获：await 配合 try...catch 可以更直观地处理异步异常。

常见坑：

- 忽略了 await 之后的代码会进入微任务队列。

- 在forEach循环中使用await无法按预期顺序执行。

追问：

- 如果 Promise.all 中有一个请求失败了，如何保证其他请求的结果依然能拿到？

### 在处理 AI 流式输出时，Fetch API 的 ReadableStream 应该如何使用？

ReadableStream 允许在数据完全到达前逐块处理，这在 AI 对话场景中实现打字机效果至关重要。

- 获取读取器：通过 response.body.getReader() 获取 reader 对象。

- 循环读取：使用 while 循环配合 reader.read() 递归读取 chunk 数据。

- 解码数据：利用 TextDecoder 将 Uint8Array 字节流转换为字符串。

- 边界处理：需要处理 chunk 截断导致的 JSON 解析失败问题。

常见坑：

- 忘记处理 reader.read() 返回的 done 状态导致死循环。

- 没有正确处理网络中断时的资源释放。

追问：

- 如果后端返回的是 Server-Sent Events (SSE)，前端除了 Fetch 还有什么原生 API 可以用？

### 谈谈你对 TypeScript 中泛型的理解，在封装 AI 模型接口时如何应用？

泛型是指在定义函数或类时不预先指定具体类型，而在使用时才指定类型的一种特性。

### 手写题：实现一个带有并发限制的异步调度器。

在调用AI接口时，为了防止瞬时请求过多导致浏览器卡死或触发限流，需要控制并发数。

- 任务队列：使用数组存储待执行的任务。

- 计数器：记录当前正在执行的任务数量。

- 递归执行：当一个任务完成后，自动从队列中取下一个任务执行。

- 返回 Promise：确保调度器支持 await 任务完成。

```javascript
class Scheduler {
    constructor(limit) {
    this.limit = limit;
    this.running = 0;
    this.queue = [];
    }
    add(fn) {
    return new Promise(resolve => {
    this.queue.push({ fn, resolve });
    this.run();
    });
    }
    run() {
    while (this.running < this.limit && this.queue.length) {
    this.running++;
    const { fn, resolve } = this.queue.shift();
    fn().then(() => {
    this.running--;
    resolve();
    this.run();
    });
    }
    }
}
```

#### 常见坑：

- 任务执行失败时没有减少 running 计数，导致后续任务无法执行。

### 介绍一下 CSS 中的 Flex 布局和 Grid 布局在复杂 AI 界面中的选型建议。

Flex 是一维布局，适合处理局部组件的排列；Grid 是二维布局，适合处理整体框架的划分。

- Flex 场景：对话列表、按钮组、导航栏等线性排列。

- Grid 场景：多模态展示区、复杂的金融数据看板、AI 工作流画布。

- 响应式：Grid在处理行列跨度（Span）时比Flex更简洁。

- 性能：对于简单布局 Flex 渲染效率略高，复杂嵌套建议用 Grid 减少层级。

- 在 Flex 容器中错误地使用 z-index。

- 忽略了 Grid 在旧版浏览器的兼容性。

### 解释一下 JavaScript 的事件循环（Event Loop）机制。

事件循环是JS处理非阻塞I/O的核心机制，通过任务队列协调同步与异步代码的执行。

- 执行栈：同步代码按顺序压栈执行。

- 微任务（Microtask）：Promise.then、MutationObserver，在当前宏任务结束前清空。

- 宏任务（Macrotask）：setTimeout、setInterval、I/O，由宿主环境发起。

- 渲染时机：浏览器通常在微任务队列清空后、下一个宏任务开始前进行页面渲染。常见坑：

- 误以为 Promise 构造函数里的代码是异步的。

- 在微任务中递归创建微任务导致页面假死。

### 如何处理 AI 生成内容中的 Markdown 渲染和代码高亮?

AI返回的通常是原始Markdown字符串，需要经过解析和安全过滤后渲染为HTML。

### 什么是防抖（Debounce）和节流（Throttle）？在 AI 交互中有哪些应用场景？

防抖是在事件触发后延迟执行，若期间再次触发则重新计时；节流是规定时间内只执行一次。

- 防抖场景：AI搜索框的实时联想、Prompt模板编辑器的自动保存。

- 节流场景：对话列表滚动加载、窗口大小调整（Resize）导致的布局重绘。

- 实现原理：防抖靠闭包维护 timer，节流靠时间戳或标志位。

常见坑：

- 忘记在组件销毁时清除定时器导致内存泄漏。

- 在高频触发场景下没有考虑 this 指向问题。

### 手写题：实现一个深拷贝函数，考虑循环引用。

深拷贝需要递归处理对象属性，并解决循环引用导致的死循环问题。

- 类型判断：区分基本类型、数组、对象、Date、RegExp等。

- 递归处理：遍历对象键值对进行深度复制。

- 循环引用：使用WeakMap存储已拷贝的对象引用。

- 性能考虑：WeakMap 相比 Map 更利于垃圾回收。

```javascript
function deepClone(obj, map = new WeakMap()) {
    if (obj === null || typeof obj != 'object') return obj;
    if (map.has(obj)) return map.get(obj);
    let target = Array.isArray(obj) ? [] : {};
    map.set(obj, target);
    Reflect_ownKeys(obj).forEach(key => {
    target[key] = deepClone(obj[key], map);
    });
    return target;
}
```

### 为什么在 AI 对话场景中 SSE 比 WebSocket 更常用？两者在前端实现上有何区别？

SSE 是一种基于 HTTP 的单向推送协议，非常适合 AI 这种 “一问多答” 且不需要双向实时通信的场景。

- 协议开销：SSE基于标准HTTP，更轻量，支持自动重连；WebSocket是独立协议，握手较重。

- 数据格式：SSE 默认传输文本流，天然契合 LLM 的 Token 输出；WebSocket 支持二进制。

- 兼容性：SSE受限于HTTP连接数限制（HTTP/1.1浏览器限制6个），需配合HTTP/2使用。

- 实现区别：EventSource 只能发 GET 请求，若要发 POST 传复杂 Prompt，需用 Fetch 模拟 SSE。常见坑：

- 忘记在后端设置 Cache-Control: no-cache 导致流式输出被缓存。

- 没处理好多标签页下 SSE 连接数超限的问题。

### 谈谈 React Fiber 架构是如何提升复杂 AI 应用性能的？

#### 难度：★★★

Fiber 引入了时间分片和优先级调度的概念，解决了 React 在处理大量 DOM 更新时的卡顿问题。

- 任务拆分：将渲染工作拆分为微小的 Fiber 单元，支持中断和恢复。

- 优先级调度：AI流式输出的文本更新属于高优先级，后台数据统计属于低优先级。

- 双缓存技术：在内存中构建新树，完成后一次性提交到真实DOM。

- 协调算法：通过 key 值比对实现高效的 Diff。

常见坑：

- 误以为Fiber缩短了总渲染时间，实际上它只是让渲染过程更平滑。

- 在 render 阶段执行有副作用的操作。

### 手写题：实现一个简单的自定义 Hook useChatScroll，处理聊天列表自动滚动。

该 Hook 需要判断用户是否处于 “底部锁定” 状态，决定是否随新消息滚动。

- 状态记录：记录滚动条位置。

- 阈值判断：如果用户向上滚动超过一定距离，则停止自动滚动。

- 监听变化：使用MutationObserver或useEffect监听消息列表长度变化。

```txt
- 滚动平滑：使用 scrollTo({ behavior: 'smooth' })。
```

```javascript
function useChatScroll(ref, deps) {
    const isAtBottom = useRef(true);
    const handleScroll = () => {
    const { scrollTop, scrollHeight, clientHeight } = ref.current;
    isAtBottom.current = scrollHeight - scrollTop - clientHeight < 50;
    };
    useEffect(() => {
    if (isAtBottom.current && ref.current) {
    ref.current.scrollTop = ref.current.scrollHeight;
    }
    }, deps);
    return { handleScroll };
}
```

### 聊聊你在过去一年中遇到的最具有挑战性的 AI 前端技术问题，你是如何解决的？

- 问题定义：准确定位技术瓶颈（如：长文本流式渲染导致的内存溢出）。

- 方案对比：列举尝试过的多种方案（如：Canvas 渲染 vs DOM 虚拟化）。

- 最终决策：说明选择该方案的理由及最终达成的业务指标（如：首字延迟降低 $50\%$ ）。常见坑：

- 描述过于笼统，没有具体的技术细节。

- 夸大自己的贡献，经不起细节追问。

### 如果公司要自研一个低代码平台结合 AI 生成 UI，你会如何设计这个流程？

AI + LowCode 的核心是将自然语言转化为结构化的 DSL（领域特定语言）。

- 语料准备：构建组件库的 DSL 描述文档，让 AI 理解每个组件的 Props 和用法。

- 迭代生成：用户输入需求 -> AI 生成 DSL 片段 -> 渲染引擎实时预览 -> 用户反馈修正。

- 协同编辑：支持人工在AI生成的基础上进行可视化拖拽微调。

- 闭环优化：记录用户对AI生成结果的修改行为，反哺Fine-tuning提升准确率。常见坑：

- AI 生成的代码不可维护，无法进行二次手动修改。
