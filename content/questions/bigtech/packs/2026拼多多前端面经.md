### 简单介绍一下CSS的盒模型，以及如何切换它们？

盒模型是浏览器对页面元素进行布局的基础，它规定了元素的内容、内边距、边框和外边距如何结合在一起。

- 标准盒模型：width 和 height 只包含 content，不包含 padding 和 border。

- IE 盒模型（怪异盒模型）：width 和 height 包含了 content、padding 和 border。

- 切换方式：使用 box-sizing 属性，content-box 对应标准模型，border-box 对应 IE 模型。

- 实际应用：现代开发通常推荐使用 border-box，因为它更符合直觉，方便计算布局尺寸。常见坑：

- 混淆两种模式下 width 的实际含义。

- 忽略了 padding 和 border 会撑开标准盒模型元素的情况。

- 如果给一个元素设置 padding: $10\%$ ，它是相对于谁的百分比？

#### 2. 说一下 JavaScript 的事件循环机制（Event Loop）

### 手写一个 Promise.all 的实现

事件循环是 JavaScript 处理非阻塞 I/O 的核心机制，通过任务队列的调度实现单线程下的异步编程。

- 任务分类：分为宏任务（setTimeout, setInterval, I/O）和微任务（Promise.then, MutationObserver）。

- 执行顺序：先执行同步代码，然后清空当前的微任务队列，再取出一个宏任务执行，执行完后再清空微任务队列。

- 渲染时机：浏览器通常会在一轮事件循环结束、微任务清空后，根据需要进行页面渲染。

- Node.js 差异：Node.js 的事件循环阶段更多（如 poll, check 阶段），与浏览器端在某些版本表现不同。

#### 常见坑：

- 认为 Promise 构造函数里的代码是异步的。

- 混淆 await 后面的代码执行时机。

#### 3. 手写一个 Promise.all 的实现

### 闭包是什么？它在实际开发中有什么应用场景？

Promise.all 接收一个 Promise 实例数组，只有当所有实例都成功时才返回成功结果数组，只要有一个失败就立即返回失败。

- 输入处理：需要处理非 Promise 类型的元素，将其包装为 Promise。

- 计数器机制：维护一个计数器记录已完成的数量，当计数器等于数组长度时resolve。

- 顺序保证：结果数组的顺序必须与输入数组的顺序一致，不能按完成先后顺序排列。

- 错误处理：任何一个 Promise 失败，直接 reject 整个结果。

代码示例：

```javascript
1 function promiseAll(promises) {
2    return new Promise((resolve, reject) => {
3    if (!Array.isArray(promises)) return reject(new TypeError('Arguments must be an array'));
4    let resolvedCount = 0;
5    const results = [];
6    promises.forEach((p, index) => {
7    Promise.resolve(p).then(res => {
8    results[index] = res;
9    resolvedCount++;
10    if (resolvedCount === promises.length) resolve(results);
11    }, err => reject(err));
12    });
13    });
14 }
```

#### 常见坑：

- 结果数组顺序错乱（直接用 push 而不是通过索引赋值）。

- 没有处理空数组的情况。

#### 4. 闭包是什么？它在实际开发中有什么应用场景？

### 谈谈你对原型链的理解，Object 和 Function 的关系是怎样的？

闭包是指一个函数能够访问其定义时所在的词法作用域，即使该函数是在作用域之外执行的。

- 核心原理：函数执行上下文销毁后，其引用的外部变量依然保留在堆内存中。

- 应用场景：封装私有变量、柯里化函数、防抖节流函数、模块化开发。

- 内存风险：如果不手动解除引用，闭包会导致变量常驻内存，可能引起内存泄漏。

- 作用域链：闭包通过作用域链查找变量，查找过程是从内向外的。

常见坑：

- 在循环中使用 var 定义变量导致闭包引用同一个值。

- 滥用闭包导致性能下降。

#### 5. 谈谈你对原型链的理解，Object 和 Function 的关系是怎样的？

### 常见的 HTTP 状态码有哪些？301 和 302 有什么区别？

原型链是JS实现继承的机制，每个对象都有一个指向其原型对象的内部链接，直到指向null。

- 原型对象：每个函数都有prototype属性，每个实例对象都有proto属性。

- 顶层结构：Object.prototype 是原型链的终点（null 之前）。

- 函数特殊性：Function 也是对象，Function.proto 指向 Function.prototype，Object 是 Function 的实例。

#### 6. 常见的 HTTP 状态码有哪些？301 和 302 有什么区别？

### 解释一下浅拷贝和深拷贝，如何实现一个深拷贝？

HTTP 状态码用于表示服务器对请求的处理结果，分为五类（1xx 到 5xx）。

- 2xx 成功：200 OK，204 No Content。

- 3xx重定向：301永久重定向（浏览器会缓存），302临时重定向。

- 5xx 服务端错误：500 Internal Server Error，502 Bad Gateway，503 Service Unavailable。

- 301 vs 302：301对SEO友好，搜索引擎会更新索引；302则不会。

- 认为304是错误码（其实是命中协商缓存）。

- 不清楚401和403的本质区别。

#### 1. React 的 Fiber 架构解决了什么问题？它的原理是什么？

### 你们项目里是如何做性能优化的？有哪些具体的指标？

Fiber 是 React 16 引入的新的协调引擎，主要解决了大型应用在更新时导致的页面卡顿问题。

- 核心问题：旧版 Stack Reconciler 递归更新不可中断，长时间占用主线程导致掉帧。

- 任务拆分：将更新过程拆分为多个小的Fiber单元，使得渲染过程可以被中断、恢复。

- 优先级调度：通过 Scheduler 给不同任务分配优先级（如用户输入高于数据请求）。

- 双缓存技术：维护 current 树和 workInProgress 树，在内存中构建好后再统一替换。常见坑：

- 误认为Fiber提高了单次计算的速度（实际上增加了计算量，但提高了响应性）。

- 不清楚哪些阶段可以中断（Reconciliation 可中断，Commit 不可中断）。

#### 2. 谈谈 Webpack 的构建流程，Loader 和 Plugin 有什么区别？

### Vue 3 的响应式原理与 Vue 2 有什么区别?

Webpack 是一个静态模块打包工具，其流程可以概括为初始化、编译、输出三个阶段。

- 构建流程：读取配置 -> 启动插件 -> 解析入口 -> 递归编译模块（Loader 转换） -> 确定依赖 -> 生成 Chunk -> 输出文件。

- Loader：本质是翻译官，将非JS文件（如CSS,图片）转换为Webpack 能处理的模块，在module.rules 中配置。

- Plugin：基于事件流（Tapable），在 Webpack 生命周期钩子中执行特定任务（如压缩、定义变量），在 plugins 数组中配置。

- 运行顺序：Loader 是从右往左（或从下往上）执行的。

常见坑：

- 无法准确描述 Plugin 的触发时机。

- 不清楚Loader为什么是链式调用的。

#### 5. 浏览器缓存策略（强缓存与协商缓存）的具体流程

### 虚拟列表（Virtual List）的实现原理是什么？

浏览器缓存通过减少重复请求来提升加载速度，分为强缓存和协商缓存。

- 强缓存：由Expires（绝对时间）和Cache-Control（相对时间，优先级高）控制，命中则不发请求。

- 协商缓存：强缓存失效后，携带 ETag 或 Last-Modified 发请求，服务器对比后返回 304 或 200。

- ETag 优势：比 Last-Modified 更精确，解决了文件修改时间变了但内容没变的问题。

- 存储位置：Memory Cache（内存）和 Disk Cache（硬盘）。

- 认为协商缓存不发 HTTP 请求。

- 混淆了 no-cache（发请求确认）和 no-store（不缓存）。

#### 9. 什么是跨域？常见的解决方案有哪些？

#### 10. Webpack 的 Tree Shaking 原理是什么?

### 如何实现一个简单的微前端架构？

Tree Shaking 是指在打包时去除代码中未引用的部分（死代码），以减小包体积。

- 静态分析：依赖于ES Modules的静态结构（import/export），在编译时即可确定依赖关系。

- 使用 CommonJS 导致 Tree Shaking 失效。

Hooks 必须在函数顶层调用，不能在循环、条件或嵌套函数中调用。

- 闭包陷阱：useEffect等Hook捕获的是某次渲染时的props和state。

#### 5. 如何处理前端的大规模数据渲染和计算？

### 假设项目上线后出现紧急 Bug，你的排查和处理流程是怎样的？

当数据量达到万级甚至十万级时，必须避开主线程阻塞和频繁DOM操作。

- 渲染优化：虚拟列表（只渲染可视区）、时间分片（Time Slicing，如 React Concurrent Mode）。

- 计算优化：将耗时计算移入Web Workers，避免阻塞UI响应。

- 数据结构：使用更高效的数据结构（如Map/Set替代数组查找），减少不必要的响应式包装。

- 预处理：后端分页、前端按需加载、数据压缩传输。
