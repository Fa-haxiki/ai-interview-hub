### 简单介绍一下 JavaScript 的事件循环机制，特别是微任务和宏任务的执行顺序。

事件循环是JS处理异步操作的核心机制，通过任务队列的循环调度确保单线程下的非阻塞运行。

- 执行栈清空后，优先处理所有微任务队列中的任务

- 微任务处理完后，取出一个宏任务执行

- 常见的宏任务包括 setTimeout、setInterval、I/O操作

- 常见的微任务包括 Promise.then、MutationObserver、process.nextTick

- 误以为Promise构造函数内部是异步的（其实是同步执行）

- 忽略了 await 后面的代码会被包装成微任务

### 说一下 SSE (Server-Sent Events) 的原理，它和 WebSocket 有什么区别？

SSE 是一种基于 HTTP 协议的单向通信机制，允许服务器主动向客户端推送文本数据。

- 协议基础：基于标准 HTTP，设置 Content-Type 为 text/event-stream

- 连接特性：长连接，支持自动重连

- 数据格式：以 data: 开头的特定文本格式

- 浏览器对同域名下 SSE 连接数有限制（通常为 6 个）

- 必须保证服务端不进行 gzip 缓冲，否则数据无法实时到达追问：

### 算法题：实现一个 LRU (最近最少使用) 缓存。

LRU缓存需要在达到容量上限时，删除最久未使用的数据，通常使用Map或双向链表实现。

- 数据结构：利用Map的有序性（插入顺序）

- get 操作：获取值后，先删除再重新插入，使其变为“最近使用”

- put 操作：如果已存在则更新并移到末尾；如果超出容量，删除 Map 的第一个元素

- 时间复杂度：get 和 put 都要求 O(1)

常见坑：

- 忘记在更新值时调整顺序

- 容量边界条件处理不当

### 在 LLM 开发中，Token 的含义是什么？为什么前端需要关注 Token 计数？

Token 是模型处理文本的最小单位，可以是一个词、一个字符或子词。

- 计费基础：API调用通常按Token数量收费

- 上下文限制：模型有最大上下文长度（Context Window），超过会截断

- 前端职责：在发送请求前预估 Token，防止超出限制或进行长文本截断优化

- 转换关系：通常1000 Token约等于750个英文单词

### 解释一下 JavaScript 中的闭包，并说明它可能导致的内存泄漏场景。

闭包是指一个函数可以访问其定义时所在的词法作用域，即使该函数在作用域之外执行。

- 核心：函数 + 词法环境引用

- 场景：私有变量、柯里化、回调函数

- 内存泄漏：如果闭包长期存在且引用了大量内存的对象，会导致该对象无法被GC回收

- 解决方法：手动解除引用（置为 null）或注意生命周期管理常见坑：

### 详细描述一下 RAG (检索增强生成) 的完整技术链路。

RAG 通过从外部知识库检索相关信息并将其注入 Prompt，来解决 LLM 知识滞后和幻觉问题。

- 索引阶段：文档清洗 -> 分块 (Chunking) -> 向量化 (Embedding) -> 存入向量数据库

- 检索阶段：用户 Query 向量化 -> 相似度检索 (Top-K) -> 召回相关文本块

- 生成阶段：将检索到的文本 + 用户 Query 拼接成 Prompt -> 调用 LLM 生成回答

- 优化：重排序 (Rerank)、多路召回、上下文压缩

常见坑：

- 分块策略不当导致语义断裂

- 检索到的无关信息干扰模型生成

### 什么是向量数据库？为什么在 AI 应用中它比传统数据库更合适？

向量数据库专门用于存储和检索高维向量数据，通过计算向量间的距离（如余弦相似度）来实现语义搜索。

- 语义检索：传统数据库基于关键词匹配，向量数据库基于语义相似度

- 高维索引：使用HNSW、IVF等算法加速大规模向量查找

- 存储内容：存储 Embedding 向量及其对应的元数据（Metadata）

- 应用：长短期记忆实现、相似图片搜索、推荐系统常见坑：

- 忽略了元数据过滤（Metadata Filtering）的重要性

### 详细说明 LLM 的 Function Calling (函数调用) 是如何实现的?

Function Calling 允许模型根据用户意图决定调用哪些预定义的函数，并生成符合函数参数格式的 JSON。

- 定义阶段：在请求中传入 functions 列表（包含名称、描述、参数 Schema）

- 识别阶段：模型判断是否需要调用函数，若需要则返回 call\_id 和参数

- 执行阶段：开发者在本地/后端执行该函数，获取结果

- 反馈阶段：将函数执行结果再次发送给模型，由模型总结成自然语言常见坑：

### 谈谈你对 AI 驱动的前端开发流程（如 Copilot, Cursor）的看法，它会如何改变我们的工作？

AI工具将前端开发从“写代码”转向“评审代码”和“系统设计”。

- 效率提升：重复性的样板代码、单元测试、类型定义由AI快速生成

门槛降低：非专业人员可以通过自然语言构建简单应用

- 核心价值：工程师的价值更多体现在架构设计、复杂逻辑抽象、性能调优和AI无法感知的业务理解上

- 风险：过度依赖可能导致基础能力退化，代码质量需要更严格的Code Review常见坑：

- 盲目信任AI生成的代码，引入安全漏洞或性能隐患

### 在有赞这样的电商 SaaS 场景下，你认为 AI 最大的落地机会在哪里？

AI 在电商领域可以深度参与营销、客服、运营等多个环节。

- 智能导购：基于用户画像和商品库的个性化推荐与咨询

- 自动化运营：AI 自动生成商品详情页、营销海报、直播脚本

- 提效工具：帮助商家快速分析报表、诊断店铺问题并给出优化建议

- 客户服务：高准确率的自动售后处理和投诉预警常见坑：

- 脱离业务场景谈技术，方案无法闭环

- 忽略了商家对成本和确定性的要求

### 如何在项目中控制大模型调用的 Token 成本?

成本控制需要通过精细化的上下文管理和模型选型来实现。

- 模型分级：简单任务用轻量模型（如GPT-3.5/Claude Haiku），复杂任务用旗舰模型

- 上下文压缩：只保留最近的对话记录，或者对旧对话进行摘要总结

- 缓存机制：利用供应商提供的 Prompt Caching 减少重复输入的计费

- 任务合并：将多个小任务合并为一个 Prompt 请求常见坑：

- 每次请求都发送全量历史记录

- 频繁调用 Embedding 模型处理重复文档

### 团队协作中，如何制定一套 AI 应用开发的规范或标准？

规范化有助于提升代码质量和 AI 输出的稳定性。

- Prompt 管理规范：版本化管理 Prompt，禁止在代码中硬编码长文本

- 接口协议规范：统一流式输出格式、错误码定义

- 评测规范：上线前必须通过标准测试集的 Benchmark

- 监控规范：强制接入 Token 消耗和响应耗时监控

- 安全规范：明确敏感数据处理流程和 Prompt 审计要求常见坑：

- 各个项目组 Prompt 风格迥异，难以维护

- 缺乏统一的AI基础设施（如API网关、向量库）导致重复造轮子
