### 说一下 JavaScript 的事件循环机制（Event Loop）。

事件循环是JS处理异步任务的核心机制，通过任务队列的调度实现非阻塞I/O。

- 执行栈与任务队列：先执行同步代码，再处理异步回调。

- 微任务（Microtask）：Promise.then、MutationObserver、process.nextTick。

- 宏任务（Macrotask）：setTimeout、setInterval、I/O、UI 渲染。

- 执行顺序：执行一个宏任务 -> 清空所有微任务 -> 渲染页面 -> 下一个宏任务。

常见坑：

- 错误地认为 setTimeout(0)会立即执行。

- 不清楚 await 后面的代码会被包装成微任务。

### 手写实现一个 Promise.all 方法。

Promise.all 接收一个 Promise 数组，只有当所有 Promise 都成功时才返回成功结果数组，只要有一个失败就立即返回失败。

- 输入处理：需要处理非 Promise 类型的元素。

- 计数器机制：维护一个已完成的任务计数，当计数等于数组长度时 resolve。

- 顺序保证：返回的结果数组顺序必须与输入数组顺序一致。

- 错误处理：任何一个任务 reject 都要直接调用 reject。

```javascript
1 function promiseAll(promises) {
2    return new Promise((resolve, reject) => {
3    const result = [];
4    let count = 0;
5    promises.forEach((p, index) => {
6    Promise.resolve(p).then(res => {
7    result[index] = res;
8    count++;
9    if (count === promises.length) resolve(result);
10    }, err => reject(err));
11    });
12    });
13 }
```

### 解释一下 JS 中的原型链以及如何实现继承。

原型链是JS实现对象间属性共享和继承的机制，每个对象都有一个指向其构造函数原型的内部链接。

### 谈谈 HTTP 缓存策略（强缓存与协商缓存）。

HTTP 缓存通过减少重复的网络请求来提升页面加载速度，分为强缓存和协商缓存两个阶段。

- 强缓存：通过 Cache-Control（max-age）或 Expires 判断，命中则不发请求。

- 协商缓存：强缓存失效后，携带 If-None-Match (Etag) 或 If-Modified-Since 请求服务器。

- 状态码：强缓存命中返回 200 (from cache)，协商缓存命中返回 304 (Not Modified)。

- 优先级：Cache-Control 优先级高于 Expires，Etag 优先级高于 Last-Modified。

- 认为304也会传输完整的响应体。

- 不清楚 Etag 解决的是 Last-Modified 时间精度不够的问题。

### Flex 布局中 flex:1 代表什么意思?

flex: 1 是一个简写属性，它决定了元素在主轴方向上如何分配剩余空间。

- 组成部分：它是flex-grow:1、flex-shrink:1和flex-basis: $0\%$ 的缩写。

- flex-grow：定义放大比例，1表示占用所有剩余空间。

- flex-shrink：定义缩小比例，1表示空间不足时等比缩小。

- flex-basis：定义在分配多余空间之前的基准大小。

### 什么是闭包？它有哪些应用场景和副作用？

闭包是指有权访问另一个函数作用域中变量的函数，本质是函数与其词法环境的引用捆绑。

- 形成条件：函数嵌套且内部函数引用了外部函数的变量。

- 应用场景：封装私有变量、柯里化（Currying）、防抖节流函数。

- 内存影响：闭包会导致外部函数的变量常驻内存，无法被垃圾回收。

- 解决内存泄漏：手动将引用置为 null。

常见坑：

- 在循环中使用var定义变量导致闭包取值错误（经典面试题）。

- 过度使用闭包导致性能下降。

### 算法题：将一个扁平的数组转换为树形结构。

给定一个包含 id 和 parentId 的对象数组，将其转换为嵌套的树形结构。

- 遍历逻辑：一次遍历，根据parentId 将当前节点挂载到父节点的 children 数组中。

- 根节点判断：parentId为空或特定值的作为根节点。

- 空间换时间：使用对象引用特性，避免多次递归查找。

```javascript
function arrayToTree(list) {
    const map = {}, res = [];
    list.forEach(item => map[item.id] = { ...item, children: [] });
    list.forEach(item => {
    const parent = map[item.parentId];
    if (parent) parent.children.push(map[item.id]);
    else res.push(map[item.id]);
    });
    return res;
```

### 谈谈 React Fiber 架构解决了什么问题？它的工作原理是什么？

Fiber 是 React 16 引入的新的协调引擎，主要解决了大型应用在更新时导致的页面卡顿问题。

- 核心问题：旧版 Stack Reconciler 递归更新不可中断，长期占用主线程导致掉帧。

- 任务拆分：将更新过程拆分为多个小任务（Work In Progress），支持中断与恢复。

- 双缓存技术：在内存中构建新的 Fiber 树，完成后一次性提交到真实 DOM。

- 优先级调度：根据任务紧急程度（如动画 $>$ 数据请求）分配执行时机。常见坑：

- 混淆了Render阶段（可中断）和Commit阶段（不可中断）。

### React 中的 Diff 算法是如何优化的?

React 的 Diff 算法通过三个前提假设，将 $O(n^{3})$ 的复杂度降低到了 $O(n)$ 。

- Tree Diff：只比较同层级节点，跨层级移动会被当作删除和新增。

- Component Diff：相同类组件生成相似树结构，不同类组件直接替换。

- Element Diff：通过 key 属性标识节点，实现节点的复用、移动和删除。

- 策略细节：仅向右移动策略，减少不必要的DOM操作。

常见坑：

- 使用数组 index 作为 key 导致的渲染性能问题或状态错误。

- 认为Diff算法会找出全局最优解（实际上是局部最优）。

### 谈谈 Canvas 和 SVG 的区别，在文档场景下如何选择？

Canvas 适合像素级操作和大量对象的频繁重绘，而 SVG 适合矢量图形和需要 DOM 事件交互的场景。

- Canvas：位图渲染，性能随画布大小变化，适合游戏、复杂动效、大数据量图表。

- SVG：矢量图，基于XML，支持CSS和事件绑定，适合图标、简单地图、文档排版。

- 文档场景：编辑器核心渲染区常选Canvas（如腾讯文档、飞书文档），以支持海量内容的高性能滚动。

- 交互处理：Canvas 需要手动计算坐标来实现点击交互，而 SVG 可以直接给元素绑事件。

- 在 Canvas 中创建过多对象导致内存溢出。

- 忽略了 Canvas 在高分屏下的模糊问题（需要处理 devicePixelRatio）。

### 协同编辑中的 OT 算法或 CRDT 算法了解吗?

协同编辑的核心是解决多个用户同时修改同一份文档时的冲突问题。

- OT (Operational Transformation): 通过操作转换，将本地操作根据远程操作进行偏移修正。

- CRDT (Conflict-free Replicated Data Types): 通过数据结构设计，保证不同副本最终一致，无需中心服务器。

- OT流程：客户端发送Op->服务器排序并广播->客户端收到后Transform。

- 适用场景：OT适合中心化系统（如腾讯文档），CRDT适合去中心化或P2P场景。

常见坑：

- 简单地认为“最后一次修改覆盖”就能解决冲突。

- 不清楚OT算法中服务端版本号的作用。

### 谈谈前端安全，如何防范 XSS 和 CSRF 攻击？

前端安全是保障用户信息和系统稳定的基础，重点在于过滤输入和验证请求来源。

- XSS (跨站脚本攻击): 通过注入恶意脚本窃取 Cookie。防范: 转义 HTML、使用 CSP（内容安全策略）、HttpOnly。

- CSRF (跨站请求伪造): 利用用户登录态发起非法请求。防范: 使用 Token 验证、SameSite Cookie 属性、验证 Referer。

- 点击劫持：通过iframe覆盖。防范：X-Frame-Options响应头。

- 数据泄露：敏感信息加密传输，避免在前端存储明文密码。

- 认为只要用了 HTTPS 就绝对安全。

- 混淆了XSS和CSRF的攻击原理。

### 虚拟列表（Virtual List）的实现原理是什么？

虚拟列表通过只渲染可视区域内的DOM节点，极大提升了处理海量数据时的渲染性能。

- 核心思路：监听滚动事件，根据 scrollTop 计算当前应显示的起始索引。

- 容器结构：一个固定高度的容器（overflow: auto）和一个撑开高度的占位元素。

- 动态偏移：使用 transform:translateY 移动显示区域，使其始终在视口内。

- 缓冲区：在可视区上下多渲染几个节点，防止滚动过快出现白屏。

- 列表项高度不固定时，计算起始索引变得复杂（需要预估高度或动态测量）。

- 频繁触发滚动事件导致性能抖动。

### 跨端技术（RN, Flutter, H5）你如何看待？在什么场景下选哪种？

跨端技术的选择本质是在开发效率、性能表现和动态性之间做权衡。

H5：开发最快，动态性最强，但性能上限低，适合营销页、简单功能。

- React Native：原生渲染，性能较好，适合追求原生体验且需要JS生态的应用。

- Flutter：自绘引擎，性能最接近原生，UI高度一致，但学习成本和包体积较大。

- 选型逻辑：核心业务追求极致体验选原生；快速迭代选H5；中大型复杂App考虑RN/Flutter。常见坑：

- 忽略了跨端方案在特定平台（如折叠屏、低端机）的兼容性坑。

- 没考虑到团队现有的技术储备。
